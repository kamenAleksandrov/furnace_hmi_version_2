# ADR-0002: Pin the production runtime to Zephyr 4.4.0

- Status: Accepted
- Date: 2026-08-24
- Governing requirements: REQ-NFR-005, REQ-NFR-009, TEST-008

## Context

The HMI needs an RTOS, driver/configuration model, multi-target build path,
testing facilities, and LVGL integration. Reproducibility requires a concrete
version rather than a moving branch.

## Decision

Use Zephyr 4.4.0 as the production HMI runtime and pin repository dependency
metadata to that release. Use the C standard required/recommended by that
configured environment and record the effective compiler standard from build
evidence. Use Zephyr devicetree, Kconfig, board configuration, drivers, and
tooling as the platform boundary.

Do not use Zephyr main, another release, or ESP-IDF as the application runtime
without a superseding decision. Zephyr's Espressif target support may use
vendor tooling internally; document that implementation dependency without
turning ESP-IDF into the HMI architecture.

## Consequences

- Toolchain, west manifest, documentation, and CI must reproduce 4.4.0.
- Security/support fixes from later releases are not adopted silently; an
  upgrade needs compatibility evidence and an ADR update.
- Target feasibility remains subject to driver maturity and resource evidence.

## Verification and follow-up

Record environment and build evidence in
[development environment](../05-platform/DEVELOPMENT_ENVIRONMENT.md) and
[status](../09-progress/STATUS.md). Build each declared target under `TEST-008`.

## Review record

Version selection is an approved project decision. This ADR does not select the
first production board or exact SDK/toolchain installation location.
